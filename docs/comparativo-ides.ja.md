# 率直な比較: IDE TEA と市場の他の IDE

<p><a href="comparativo-ides.md">Português</a> · <a href="comparativo-ides.fr.md">Français</a> · <a href="comparativo-ides.de.md">Deutsch</a> ·
<a href="comparativo-ides.it.md">Italiano</a> · <b>日本語</b> · <a href="comparativo-ides.zh-CN.md">中文（简体）</a></p>

この文書は、**IDE TEA** (現在の状態、`v0.4.0`) を、市場の主な IDE とエディターに対して、技術的に、直接、飾らずに評価します。

- **VS Code / VSCodium** (Electron ベースの、普遍的な標準)
- **Cursor / Windsurf** (AI に寄せた VS Code のフォーク)
- **Zed** (速度、共同編集、統合 AI に寄せた、Rust のネイティブ IDE)
- **JetBrains (RustRover, IntelliJ, PyCharm, CLion)** (重いセマンティック IDE)
- **Neovim / Helix / Lapce** (軽量なモーダル / ネイティブ エディター)

> **この分析の範囲:** 焦点は厳密に技術です。**安定性、性能、編集機能、LSP、デバッグ、Git、エコシステム、エージェント統合**。チームの規模や、誰がプロジェクトを保守しているかは考慮しません。

> それ以降のリリースでは、macOS (Apple Silicon) と Windows (x86_64) も配布しています。表と本文は 0.4.0 の記録のままです。「Linux のみ」のセルも含みます。

## 2. 安定性と信頼性

### IDE TEA が本当に強いところ

1. **WebView / Chromium のないアーキテクチャ:** VS Code、Cursor、Windsurf と違い、Chromium のレンダリング プロセスも、一日かけてメモリを漏らす Node.js の extension host もありません。バイナリは 1 つで、安全な Rust でコンパイルされています。
2. **拡張機能と外部プロセスの障害の隔離:**
   - 言語サーバー (`tea-lsp`)、デバッガー (`tea-dap` / `gdb`)、`git` の呼び出し、エージェントは別プロセスです。`rust-analyzer` や `gdb` が固まるか落ちても、IDE のウィンドウは固まりません。
   - 内部拡張機能は、メッセージとイベント (`Request` / `CoreEvent`) だけでコアと通信し、アプリケーション状態の可変参照を共有しません。
3. **作業を失わない保護:**
   - 未保存の変更があるタブを閉じるとき、または IDE を終了するときは、必ず確認します。
   - **障害からの自動回復 (`backup.rs`):** 未保存の変更があるタブは、PID ごとに `$XDG_STATE_HOME/idetea/backups/<プロジェクト>/` へ書かれ、ウィンドウが予期せず閉じたときに復元を提案します。
   - ツリーでのファイル削除は、**システムのゴミ箱** へ送ります (取り消せない `unlink` はしません)。
   - ディスク上の外部変更 (`git checkout`、`cargo fmt`、エージェントによるファイル編集) はウォッチャーが検出します。ローカル編集のないタブは自分で再読み込みし、未保存のローカル編集があるタブは **決して** 黙って上書きしません。
   - バイナリ、または UTF-8 でないファイルは、保存時にバッファを壊す代わりに、明確な警告で拒否します。
   - `.idetea/` の手順はアトミックな書き込み (`.tmp` + `rename`) を使い、自己回復のコマンドがあります (`idetea fix` / *「インターフェース: このプロジェクトを直す」*)。

### IDE TEA の安定性が、大手にまだ負けるところ

1. **検証は Linux (Wayland) のみ:** 現在、IDE TEA の開発と検証は Linux です。macOS と Windows には、パッケージ、フォント、ショートカット (`Cmd` と `Ctrl`)、ターミナルの PTY (Windows の `conpty`)、パスについて、実地を経ていない差があります。VS Code、JetBrains、Zed は、3 つのシステムで成熟して動きます。
2. **複雑なアプリに対する `iced` 0.14 の限界:**
   - IDE は単一ウィンドウ (`iced::application`) です。ターミナル、プレビュー、エディターを、OS の別のネイティブ ウィンドウとして第二モニターへ切り離すことはできません。
   - ファイルごとの連続したローカル履歴 (*Local History* / *Timeline*。Git なしで数日にわたる、JetBrains や VS Code のようなもの) はありません。
3. **`tree-sitter` に対する、正規表現ベースの構文強調 (`syntect`):**
   - IDE TEA は、50 MB のファイルや巨大なミニファイ行に優秀な軽量モードを持ちますが、数千行の通常のコードでは、`.sublime-syntax` の正規表現文法に基づく `syntect` は、Zed、Helix、Neovim が使う `tree-sitter` より、未完成のコードへの構造的な耐性が低いです。

## 3. AI エージェントとの流れ (IDE TEA が唯一であるところ、競わないところ)

これは、今日の市場で最も深い、製品哲学の違いです。

### Cursor、Windsurf、Zed の AI の扱い

- **エディターの中のモデル** を前提にしています。
  - 入力中に次の行を推測する *予測補完 (Tab / Next Edit Prediction)*。
  - *インライン編集 (`Ctrl+K`)* と *Composer / Agent Chat*。エディターの行のあいだに色付き差分 (緑 / 赤) を出し、hunk ごとに採用 / 拒否します。
  - 引き換えに、クラウドのアカウント、月額、または IDE 内のプロバイダー HTTP クライアントに縛られます。

### IDE TEA の AI の扱い (勝つところ)

IDE TEA は、**最良のエージェントは既にターミナルで動いている** (Claude Code、Codex、Gemini CLI、Aider、OpenCode) と仮定し、他の IDE がネイティブかつオープンには解いていない問題を解きます。**それらのエージェントが、ターミナルのテキストの壁にならずに人と話す方法** です。

1. **ネイティブな宣言的インターフェース (`.idetea/ui/` + `idetea ask`):**
   - エージェントがターミナルの 200 行のログの途中で質問する代わりに、検証済み JSON を公開し、IDE が `iced` のネイティブ フォームを描画します。セレクター、チェックボックス、手動テストの手順リスト (*承認* ボタンは、手順を満たしたあとだけ有効)、画像 / ギャラリーのプレビュー、アニメーションするスプライトシート、波形付きの WAV 音声です。
   - **市場の他の IDE (VS Code、Cursor、Zed、JetBrains) は、ターミナルのエージェントが、監査可能な履歴 (`.idetea/history/`) 付きでネイティブ UI を描く、ファイルベースの宣言的プロトコルを持っていません。**
2. **実行の統治と安全 (`idetea run`):**
   - エージェントが対話ターミナルを開くか、作業を委任したいとき、IDE は正確なコマンドを承認タブに表示します。許可コマンドのリスト (`[agents] allow`) は、利用者のグローバル設定 (`~/.config/idetea/config.toml`) からだけ読み、リポジトリからは **決して** 読みません。悪意のあるリポジトリが、自分に実行許可を与えることを防ぎます。
3. **隔離した Git worktree への委任 (`--worktree` + `$IDETEA_ANSWER`):**
   - IDE は、サブエージェントがメインのツリーを汚さずに並行作業できるよう、worktree の作成と片付けをネイティブに管理します。
4. **ネイティブな反応マスコット (Tea) + `idetea mascot`:**
   - *Masko.ai* のようなツールが、Claude Code に反応するマスコットのために macOS とクラウドの MCP サーバーを必要とする一方、IDE TEA には **Tea** がネイティブに組み込まれ、`.idetea/ui/`、`.idetea/agents/`、タスク、LSP をリアルタイムで見ます。マウスにも反応し (`curious` / `annoyed`)、`mascot.toml` のパックを受け付けます。

### IDE TEA が AI の流れで負けるところ

- **予測補完はゼロ ("ゴースト テキスト" / Tab):** 手入力のあいだに Cursor / Copilot の `Tab` で定型を補完する人に、IDE TEA の相当機能はありません。
- **エディター内の AI インライン差分表示がない:** ターミナルのエージェントがファイルを編集すると、IDE TEA のタブはファイルを再読み込みします。何が変わったかを見るには **Git** パネルへ行きます。Cursor や Windsurf のように、コード エディター内に浮く *"Accept / Reject hunk"* ボタンはありません。
- **エディターからエージェントへのコンテキスト渡しは、まだ手動:** エージェントは `idetea status` でアクティブなファイルとカーソル行を知れますが、選択範囲や LSP のエラーを、ターミナルで開いているエージェントのプロンプトへ直接送る IDE のショートカット (例: `Ctrl+L`) は、まだありません。

## 4. コード エディター: あるもの、ないもの

### IDE TEA で既に堅いもの

- ファイルの高速オープン (`Ctrl+P`。あいまい検索と、`ファイル:行` へのジャンプ)、ファイル内のシンボル (`Ctrl+Shift+O`)、プロジェクト内のシンボル (`Ctrl+T`)。
- マルチ カーソル、単語単位の選択 (`Ctrl+矢印`)、`Shift+クリック`、コードの折りたたみ、元に戻す / やり直す、ファイル内の検索と置換、**プロジェクト全体の置換 (`Ctrl+Shift+H`)**。行ごとのプレビューと、正規表現に対応します。
- エディターの一時ズーム (`Ctrl+=`、`Ctrl+-`、`Ctrl+0`、`Ctrl+スクロール`)。タブと分割のあいだで同期し、UI の残りには影響しません。
- エディターの横並び分割 (split)、クリックできるパンくずリスト (`プロジェクト › フォルダー › ファイル › シンボル`)、言語ごとの Seti アイコン、合字付きのカスタム フォント (内蔵の `JetBrains Mono`)。
- 任意の Vim モード。
- 画像のネイティブ タブ (ズームとドラッグ)、PDF (純粋な Rust の `hayro` で描画)、Markdown と SVG のリアルタイムの横並びプレビュー。

### VS Code、Zed、JetBrains と比べて、エディターにないもの

1. **スニペット:** スニペット エンジンがありません (タブ ストップ `$1`、`$2` で、短いコード片を展開)。
2. **AST による構造的選択 (選択範囲の拡大 / 縮小):** Zed、Helix、JetBrains では、ショートカットが選択を、単語 → 式 → `if` ブロック → 関数全体へ、`tree-sitter` / AST で広げます。
3. **レガシー エンコーディング:** 開くのは UTF-8 のみです (LF/CRLF は保持)。`ISO-8859-1` / `Windows-1252` のファイルは、IDE TEA では編集できません。
4. **複数ウィンドウ / 同一インスタンスの複数プロジェクト:** プロジェクトごとに別の `idetea` プロセスです。同じウィンドウの "Multi-root Workspaces" はありません。

## 5. 言語の知能 (LSP) とリファクタリング

### IDE TEA が既に良く届けているもの

- リアルタイムの診断。**エディター本文の波線**、ホバーのエラー ツールチップ、ステータス バーの件数、**問題** パネル (`Ctrl+Shift+M` / `F8`)。
- 補完、パラメーターのシグネチャ、定義へ移動 (`F12`)、型へ移動、実装へ移動 (`Ctrl+F12`)。
- 参照の検索 (`Shift+F12`、または宣言での `Ctrl+クリック`)。ファイルごとにグループ化し、戻る / 進むの履歴 (`Alt+←` / `Alt+→` と、マウスのサイド ボタン)。
- **呼び出し階層 (`Alt+Shift+H`):** 関数を呼ぶものと、関数が呼ぶもの。
- **アウトライン パネル (`Alt+7`):** ファイルのシンボル ツリー。可視性 (`pub`、`pub(crate)`、非公開) を示し、カーソル下のシンボルを強調します。
- **シンボルの名前変更 (`F2`)。** 適用前に、影響するファイル数と変更数のプレビュー ダイアログを、プロジェクト全体で出します。
- 保存時のフォーマットと、`.editorconfig` の尊重。

### VS Code、Zed、JetBrains に対する、重要な LSP の欠落

1. **コード アクション / クイック フィックスがない (`Ctrl+.` / LSP の電球):**
   - これが今日、**Rust / TypeScript / Go の日常で最も大きい実用上の欠落** です。`rust-analyzer` が *"Import `std::collections::HashMap`"*、*"Add missing match arms"*、*"Fill struct fields"* を提案しても、IDE TEA では診断メッセージは見えますが、ショートカットで *クイック フィックス* (`textDocument/codeAction`) を適用できません。
2. **インレイ ヒントがない:**
   - 推論された型をインラインで出したり (`let x: Vec<String> = ...`)、関数呼び出しのパラメーター名を出したりしません。Rust と TypeScript で、VS Code、Zed、RustRover ではよく使われる機能です。
3. **LSP のセマンティック トークンがない:**
   - 構文の色は、もっぱら `.sublime-syntax` 文法 (`syntect`) からです。LSP の意味的な補強はありません (例: 言語サーバーの色で、可変と不変の変数、またはマクロと関数を区別する)。

## 6. デバッグ

### IDE TEA が今日すること

- `gdb` 14 以降とのネイティブ統合 (DAP 経由)。行番号のクリックでブレークポイント (`F9`)。ファイルを編集するとテキストに追従します。`F5` (Rust、Zig、および実験的に MoonBit のプロジェクトでは、自動でビルドして実行)、ステップ オーバー (`F10`)、ステップ イン (`F11`)、ステップ アウト (`Shift+F11`)、一時停止、停止。
- パネルに、呼び出しスタック (クリックでフレームの行へ)、検査できるローカル変数のツリー、プログラムの出力。

### VS Code と JetBrains に負けるところ

- **GDB 14 以降に縛られる (Rust、C、C++、Zig、および実験的に MoonBit):** Python (`debugpy`)、Go (`delve`)、JavaScript/TypeScript (`js-debug`)、`codelldb` (macOS) の DAP アダプターは、まだありません。Hare には、IDE 内のデバッガーがありません。
- **高度なデバッグ機能がない:** 条件付きブレークポイント (*「`i == 42` のときだけ停止」*)、ログポイント、任意の *ウォッチ式* のウィンドウ (ブレークポイント中の REPL)、エディター内のコードの横に描く変数値はありません。

## 7. Git とバージョン管理

### IDE TEA が今日すること

- ステータス バーに、現在のブランチ、先行 / 遅れのコミット (`ahead`/`behind`)、変更されたファイルの合計。
- Git パネル。ファイル単位または全体のステージ / ステージの解除、色付き差分、コミット メッセージ欄、確認付きの変更の破棄、システムの `git` と資格情報 / SSH を使う `push`、`pull`、`fetch` のボタン。
- ファイル ツリーの Git 状態の色。

### VS Code、Zed、JetBrains に負けるところ

1. **エディター余白の Git の印 (ガター差分) がない:** ファイルの編集中、前回のコミットから追加または変更された行を示す、行番号の横の緑 / 青 / 赤の細い印がありません。
2. **インラインの Git Blame がない:** 現在の行を、誰が、どのコミットで変えたかを出しません。
3. **マージ競合の視覚的な解決 (3-way マージ) がない:** 競合は、テキストの `<<<<<<<` マーカーを編集するか、ターミナルで解決します。
4. **UI からのブランチの切り替え / 作成、または Stash がない:** ブランチの切り替え、作成、`git stash` は、統合ターミナルを使います。

## 8. 率直な要約: 今日 IDE TEA を選ぶとき (選ばないとき)

### IDE TEA が既により良いか、唯一であるとき

1. **ターミナルのエージェント (Claude Code、Codex、Gemini CLI など) のそばで、Linux 上でプログラムする** とき。エージェントに、構造化された質問、計画 / 手動テストの表示、コマンド実行の明示的な許可、隔離した worktree、反応するマスコット (**Tea**) を、クラウドや購読なしで持たせたいとき。
2. **速度、予測可能性、感覚的な雑音の少なさを優先するとき:** 200 ms 未満で開き、メモリを少ししか使わず、アカウントがなく、テレメトリがなく、UI を勝手に変えず、単純な TOML ファイルを尊重します。
3. **Rust、Zig、C/C++、Python、Go、Hare、MoonBit、Web のプロジェクト** で、主な流れが、素早い編集、LSP のシンボル / 参照での移動、統合ターミナルでのタスク / テスト、コミットの確認であるとき。

### 別の IDE の方がまだ良いとき

1. **キーごとの予測 AI 補完 (`Tab` / ゴースト テキスト)、または差分によるインライン編集が欲しいとき:** **Cursor**、**Windsurf**、**Zed** の方が、そのスタイルに合います。
2. ***コード アクション* (`Ctrl+.`) による支援付きリファクタリング、*インレイ ヒント*、または GUI の Python/JS/Go デバッガーに強く依存するとき:** **VS Code** か **JetBrains** の方が、今日はずっと完全です。
3. **macOS か Windows で働く、または SSH Remote Development / DevContainers に依存するとき:** **VS Code** と **Zed** は、これらの場面に成熟した対応を既に持っています。

## 9. 影響の大きい次の 5 歩 (IDE TEA の魂を失わずに、先頭へ近づく)

目標が、軽いバイナリとマニフェストの哲学を保ったまま、VS Code と Zed との機能的な距離を縮めることなら:

1. **LSP のコード アクション / クイック フィックス (`Ctrl+.`):** LSP サーバーが既に計算できる *クイック フィックス* と、自動 *import* を適用できるようにします。Rust/TS で最も足りない 1 番です。
2. **エディターの Git の印 (ガター差分) + ステータス バーでのブランチ切り替え:** 追加 / 変更された行を余白に示し、ステータス バーのブランチ名をクリックして、パレットでブランチを切り替えられるようにします。
3. **「選択 / 診断をエージェントへ送る」ショートカット (`Ctrl+L`):** エディター / LSP と、統合ターミナルで動くエージェントのあいだの輪を閉じます。
4. **LSP のインレイ ヒント (推論された型と、任意のパラメーター名):** 型のヒントをインラインで出し、オン / オフの短いショートカットを付けます。
5. **macOS と Windows への移植 + さらなる DAP アダプター (`lldb-dap`、`debugpy`、`delve`):** Linux の外の開発者に IDE を開き、GDB 以外のデバッグに対応します。
