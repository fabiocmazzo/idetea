A fast, quiet IDE where coding agents ask before they act. You stay in the editor. The agent stays in the terminal. The questions show up as a form, and nothing runs until you say so.

Linux (x86_64 and aarch64), macOS (Apple Silicon) and Windows (x86_64). Before 1.0.

Who it’s for. People who write code next to Claude Code, Codex, or any agent that reads AGENTS.md and CLAUDE.md, and who want the editor to open fast, stay predictable, and keep its hands off the network.

What you get

Fast

Open, then get out of the way

Starts in well under 200 ms. A 50 MB file opens in a tenth of a second. A minified file with one giant line opens in a light mode instead of freezing the window.

Quiet

No account, no telemetry, no marketplace

No pop-ups about features you did not ask for. The network is used only when you ask (push, pull, fetch, or a skill you install). Settings live in one plain TOML file.

In charge

Agents ask. You decide.

Questions are real forms: choices, checkboxes, steps, images, sounds. A terminal request shows the whole command. A project cannot put itself on your allow list.

Editor

Complete where it counts

Multi-cursor, optional vim mode, file tree, project search, LSP, git, an integrated terminal, debugging with gdb, and tabs for Markdown, SVG, images and PDF.

Small

A core that only edits files

The tree, the terminal, git and the debugger are extensions you can turn off. Tea, the pixel-art mascot, watches for a waiting question and gets out of the way when you collapse it.

Why IDE TEA

From the honest comparison with VS Code, Cursor, Zed, JetBrains and Helix. That note was written around 0.4.0. Releases since then also ship macOS (Apple Silicon) and Windows (x86_64).

This is the point

  • Terminal agents get a file-based protocol: forms, approved commands, worktrees, and the Tea mascot. The history of every answer stays in the project.
  • Start Claude Code, Codex or Gemini CLI with Ctrl+Shift+A, point Ctrl+L at the code, and keep a project memory in plain files that every agent shares.
  • No account and no telemetry. The binary does not phone home.
  • Fast open, and large or minified files that do not freeze the window.

This is not the point

  • No ghost-text autocomplete. That is a choice, not a missing switch.
  • No inline “accept this hunk” diffs. When an agent edits a file, you review it in the git panel.
  • Code actions, inlay hints and debugger coverage are behind VS Code and JetBrains. The comparison says so.

Install

Ready to run from the latest release. SHA256SUMS has the checksums.

Linux

x86_64 and aarch64, .tar.gz or .AppImage. ./install.sh puts idetea in ~/.local/bin and in the app menu. The AppImage needs chmod +x; --install-desktop adds the menu entry.

macOS

Apple Silicon, a .tar.gz with IDE TEA.app. idetea --install-desktop creates ~/Applications/IDE TEA.app.

Windows

x86_64, the -setup.exe installer or a portable .zip. Free code signing by SignPath.io, certificate by the SignPath Foundation.

From source (needs Rust stable):

cargo install --locked --git https://github.com/fabiocmazzo/idetea tea-app
idetea --install-desktop

Optional: git for the git panel, gdb 14+ (or lldb-dap on macOS) for debugging, and the language servers you use. rust-analyzer, clangd, pyright, typescript-language-server, gopls, lua-language-server, zls, zx lsp, hare-lsp (Hare) and moon lsp (MoonBit) are already set up.

About the name

It started as a pun on iced tea, because the IDE is built with iced. In Portuguese, TEA is also the acronym for autism. IDE TEA is made by an autistic developer, and it shows in what it values: low noise, clear text, things that behave the same way every time, and room to focus.
