Mit Agenten arbeiten, Schritt für Schritt

Ihr Coding-Agent läuft weiter in einem Terminal. IDE TEA gibt ihm einen Weg, Sie ordentlich zu fragen, und sorgt dafür, dass nichts ohne Ihr Wort läuft.

1. Bevor Sie anfangen

  • Ein Coding-Agent, der AGENTS.md oder CLAUDE.md liest: Claude Code, Codex und andere.
  • idetea auf Ihrem PATH (der Installer erledigt das). Agenten nutzen die Befehle idetea, wenn sie sie finden, und schreiben die Dateien sonst selbst.
  • Ein in IDE TEA geöffnetes Projekt.

2. Den Agenten des Projekts beibringen

  1. Öffnen Sie die Befehlspalette (Ctrl+Shift+P).
  2. Führen Sie Interfaces: den Agenten dieses Projekts beibringen aus.
  3. Die IDE schreibt einen kurzen Block Anweisungen in die AGENTS.md und CLAUDE.md, die Sie schon haben, und lässt den Rest jeder Datei in Ruhe. Gibt es keine von beiden, legt sie eine AGENTS.md an und eine CLAUDE.md, die sie importiert. Committen Sie sie mit dem Projekt, oder behalten Sie sie für sich: Ihre Wahl.
Der Block trägt eine Version. Wenn eine neuere IDE neuere Anweisungen hat, sagt es der Bereich; führen Sie denselben Befehl noch einmal aus.

3. Ihren Agenten in der IDE ausführen

Öffnen Sie das Terminal (Ctrl+' oder Ctrl+`; Ctrl+Shift+T öffnet die zuletzt geschlossene Registerkarte wieder) und starten Sie Ihren Agenten dort, wie überall sonst:

claude        # oder codex, oder der Agent Ihrer Wahl

Bitten Sie wie gewohnt um das, was Sie wollen. Wenn der Agent eine Entscheidung braucht, nutzt er den Bereich statt des Chats. Sie können es auch ausdrücklich sagen: „Fragen Sie mich im Bereich Interfaces“.

4. Eine Frage beantworten

Wenn der Agent etwas fragt, öffnet der Bereich Interfaces mit einem echten Formular, und die Statusleiste sagt, dass eine neue Frage angekommen ist.

  1. Füllen Sie das Formular aus: Auswahl, Kontrollkästchen, Textfelder. Eine Schaltfläche, die zuerst etwas braucht, sagt, was fehlt.
  2. Optional: schreiben Sie einen Kommentar für den Agenten (ein Vorbehalt, eine Rückfrage). Er geht mit der Schaltfläche mit, die Sie klicken.
  3. Klicken Sie eine Schaltfläche. Die Antwort geht zurück an den Agenten, der weitermacht.

Jede Frage und Ihre Antwort bleiben erhalten. Öffnen Sie den Verlauf der Interfaces (Palette oder der Link Verlauf oben im Bereich), um zuerst die offenen Fragen zu sehen und die beantworteten nach Tag, mit Suche. Ein Eintrag öffnet nur zum Lesen, so, wie Sie geantwortet haben, mit dem Zeitpunkt, an dem der Agent ihn gelesen hat.

Agenten können Ihnen auch Bilder zeigen, Galerien zur Auswahl, animierte Sprites, Klänge mit ihrer Wellenform, Dateien zum Bearbeiten (eine Commit-Nachricht, eine Beschreibung für einen PR) und Schrittlisten für einen manuellen Test, mit einer Schaltfläche zum Zustimmen, die wartet, bis Sie die Schritte erledigt haben. Text auswählen, oben an einer Oberfläche, lässt Sie ihren Text kopieren.

5. Ein Terminal zulassen

Um etwas auszuführen, das Sie beobachten können sollen (Tests, ein Entwicklungsserver, ein weiterer Agent), bittet der Agent die IDE um ein Terminal. Eine Registerkarte Terminalanfrage zeigt genau, was laufen würde, und wo.

  1. Lesen Sie den Befehl. Es läuft genau das, mit Ihren Rechten, als hätten Sie ihn getippt.
  2. Klicken Sie Zulassen und ausführen oder Ablehnen. Der Agent erfährt, was Sie gewählt haben.
  3. Der Befehl läuft in seiner eigenen Registerkarte. Wenn er endet, behält die Registerkarte die Ausgabe und den Exit-Code, bis Sie die Eingabetaste drücken; der Agent bekommt den Code (und, wenn der Befehl eine geschrieben hat, eine Antwortdatei).

Die Registerkarte vor dem Ende zu schließen stoppt den Befehl, und der Agent erfährt es.

6. Die Frage für Befehle überspringen, denen Sie vertrauen

Tragen Sie sie in Ihre Konfiguration ein, ~/.config/idetea/config.toml:

[agents]
allow = ["npm run dev", "cargo test", "claude *"]

Ein Eintrag ist der genaue Befehl oder ein Anfang gefolgt von *: dieser Anfang plus schlichte Argumente, ohne ; & | $, Backticks oder Umleitungen.

Diese Liste wird nur aus Ihrer eigenen Konfiguration gelesen. In der .idetea/config.toml eines Projekts wird sie ignoriert (mit einer Warnung): ein Agent kann Projektdateien schreiben, und ein Projekt darf sich nie selbst die Erlaubnis geben können.

7. Arbeit an einen Helfer abgeben

Ihr Agent kann einen weiteren starten, für eine Prüfung oder eine Reparatur nebenher, in seinem eigenen git-Worktree, damit die beiden nie dieselben Dateien bearbeiten:

idetea run --title "Reviewer" --worktree agent/review -- \
  claude -p 'Review the last commit. Write your findings to the file in $IDETEA_ANSWER.'
  1. Sie lassen die Anfrage zu, wie in Schritt 5. Die Registerkarte zeigt den Branch, den sie nutzen wird.
  2. Die IDE legt .idetea/worktrees/<Name> auf diesem Branch an und führt den Helfer dort aus.
  3. Der Helfer schreibt seine Antwort nach $IDETEA_ANSWER; Ihr Hauptagent liest sie und holt den Code vom Branch auf dem üblichen Weg herein (mit Ihrem Test und Ihrer Zustimmung).
  4. Wenn es fertig ist, wird der Worktree entfernt, wenn er keine uncommitteten Änderungen hat. Der Branch bleibt immer.

8. Die Befehle idetea

Agenten nutzen sie, wenn idetea auf dem PATH liegt. Jeder erledigt den ganzen Weg in einem Aufruf. Sie können sie selbst im Terminal der IDE ausprobieren.

BefehlWas er tut
idetea ask --text "Deploy now?" --confirm Zeigt eine Frage im Bereich und wartet (voreingestellt 10 Minuten). Kurze Formen: --options "a|b|c", --confirm, --input "Name"; oder ein volles Formular aus einer JSON-Datei. Gibt die Antwort aus.
idetea run --title "Tests" -- cargo test Bittet um ein Terminal, wartet auf das Ende, gibt die Antwort des Helfers aus und endet mit dem Code des Befehls (5, wenn Sie abgelehnt haben).
idetea status Was Sie offen haben: die aktive Datei mit dem Cursor, die offenen Dateien und welche ungespeicherte Änderungen haben (auch --json).
idetea open src/main.rs:42 Zeigt Ihnen eine Datei in der IDE, an dieser Zeile, ohne etwas zu fragen.
idetea history Was Sie im Bereich geantwortet haben, die älteste zuerst (--name, --since, --last N, --all, --json). Praktisch für einen Agenten, der seinen Kontext verloren hat.
idetea mascot working --text "Compiling…" Setzt Stimmung und Sprechblase des reaktiven Maskottchens in Echtzeit (idle, working, thinking, attention, celebrating, error, sleeping, curious, annoyed oder clear).

Führen Sie einen davon allein aus, um alle Optionen zu sehen.

9. Ein neues Projekt mit einem Agenten anfangen

Projekt: neu… in der Palette (oder idetea new) legt den Ordner an, führt git init aus, installiert die Agent-Skills einer Vorlage (leer, Rust, Website, Python, FastAPI), schreibt eine Anfangsanfrage in die AGENTS.md und kann Ihren Agenten in einem Terminal der IDE öffnen, damit Sie zustimmen:

idetea new my-app --modelo rust --descricao "a unit converter" --agente claude

10. Darunter

Alles sind schlichte Dateien im Ordner .idetea/ des Projekts. Diese bleiben außerhalb von git:

  • .idetea/ui/<Name>.json: eine Frage; Ihre Antwort landet in .idetea/ui/responses/.
  • .idetea/agents/<Name>.json: eine Terminalanfrage; ihr Fortschritt in <Name>.status.json.
  • .idetea/state.json: was Sie offen haben, für idetea status.
  • .idetea/mascot.json: optionaler Zustand und Sprechblase, gesendet über idetea mascot.
  • .idetea/history/: jede Frage und Antwort, bis Sie ihn leeren.

Also kann jeder Agent, der Dateien lesen und schreiben kann, es nutzen, und Sie können jede Nachricht selbst lesen. Die vollständigen Formate (vorerst auf Portugiesisch): das Format von Interfaces und Agenten-Terminals.
