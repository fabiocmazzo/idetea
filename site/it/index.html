Un IDE veloce e silenzioso, dove gli agenti di codice chiedono prima di agire. Tu resti nell'editor. L'agente resta nel terminale. La domanda compare come un modulo, e non parte niente finché non lo dici tu.

Linux (x86_64 e aarch64), macOS (Apple Silicon) e Windows (x86_64). Prima della 1.0.

Per chi è. Per chi scrive codice accanto a Claude Code, Codex o qualsiasi agente che legga AGENTS.md e CLAUDE.md, e vuole un editor che si apra in fretta, resti prevedibile e non tocchi la rete.

Che cosa ottieni

Veloce

Si apre, e poi si toglie di mezzo

Parte ben al di sotto dei 200 ms. Un file da 50 MB si apre in un decimo di secondo. Un file minificato, con una riga enorme, si apre in una modalità leggera invece di bloccare la finestra.

Silenzioso

Niente account, niente telemetria, niente marketplace

Niente finestre su funzioni che non hai chiesto. La rete si usa solo quando lo chiedi tu (push, pull, recupera, o una skill che installi). Le impostazioni stanno in un unico file TOML, in chiaro.

Al comando

L'agente chiede. Decidi tu.

Le domande sono moduli veri: scelte, caselle, passi, immagini, suoni. Una richiesta di terminale mostra il comando intero. Un progetto non può mettersi da solo nel tuo elenco consentiti.

Editor

Completo dove conta

Più cursori, modalità vim facoltativa, albero dei file, ricerca nel progetto, LSP, git, un terminale integrato, debug con gdb, e schede per Markdown, SVG, immagini e PDF.

Piccolo

Un nucleo che modifica solo file

L'albero, il terminale, git e il debugger sono estensioni che puoi spegnere. Tea, la mascotte in pixel art, tiene d'occhio una domanda in attesa e si toglie di mezzo quando la comprimi.

Perché IDE TEA

Dal confronto onesto con VS Code, Cursor, Zed, JetBrains e Helix. Quella nota è stata scritta intorno alla 0.4.0. Le versioni successive escono anche per macOS (Apple Silicon) e Windows (x86_64).

Il punto è questo

  • Gli agenti nel terminale hanno un protocollo fatto di file: moduli, comandi approvati, worktree e la mascotte Tea. La cronologia di ogni risposta resta nel progetto.
  • Niente account e niente telemetria. Il binario non chiama casa.
  • Si apre in fretta, e i file grandi o minificati non bloccano la finestra.

Il punto non è questo

  • Niente autocompletamento fantasma. È una scelta, non un interruttore che manca.
  • Niente diff «accetta questo hunk» in linea. Quando un agente modifica un file, lo rivedi nel pannello git.
  • Code action, inlay hint e copertura del debugger sono indietro rispetto a VS Code e JetBrains. Il confronto lo dice.

Installazione

Pronto all'uso dall'ultima release. SHA256SUMS ha le somme di controllo.

Linux

x86_64 e aarch64, .tar.gz o .AppImage. ./install.sh mette idetea in ~/.local/bin e nel menu delle applicazioni. L'AppImage ha bisogno di chmod +x; --install-desktop aggiunge la voce di menu.

macOS

Apple Silicon, un .tar.gz con IDE TEA.app. idetea --install-desktop crea ~/Applications/IDE TEA.app.

Windows

x86_64, l'installer -setup.exe o uno .zip portatile. Firma gratuita di SignPath.io, certificato della SignPath Foundation.

Dal codice sorgente (serve Rust stable):

cargo install --locked --git https://github.com/fabiocmazzo/idetea tea-app
idetea --install-desktop

Facoltativi: git per il pannello git, gdb 14+ (o lldb-dap su macOS) per il debug, e i server di linguaggio che usi. rust-analyzer, clangd, pyright, typescript-language-server, gopls, lua-language-server, zls, zx lsp, hare-lsp (Hare) e moon lsp (MoonBit) sono già configurati.

Sul nome

È nato da un gioco di parole su iced tea, il tè freddo, perché l'IDE è fatto con iced. In portoghese, TEA è anche la sigla dell'autismo (disturbo dello spettro autistico). IDE TEA è fatto da uno sviluppatore autistico, e si vede in quello che conta: poco rumore, testo chiaro, cose che si comportano sempre allo stesso modo, e spazio per concentrarsi.
